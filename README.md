# 自动剪辑

## 完整安装包与运行依赖（0.1.12）

Windows 完整版 `Automated-Video-Editing-0.1.12-Windows-x64-Setup.exe` 包含 Electron、
Python 后端、FFmpeg/FFprobe、字幕字体及预览字形、BAAI INT8 模型和 tokenizer，以及
ONNX Runtime、librosa、NumPy/SciPy、Numba、soundfile、soxr 所需运行文件。
客户无需安装 Python、Node、pip 或另行下载模型。外部媒体工具版不含 FFmpeg，不属于完整包。
LLM 润色、云端 TTS 和特效生成仍需要配置相应服务并联网；这与安装依赖是两回事。

发布流水线对冻结后的程序运行 `--check-bundled-runtime`，实际执行本地模型推理、音频
解码及音乐分析子进程、音频原生库、字幕渲染与视频探测。检查失败时不继续生成完整安装包。
前端皮肤为本地 CSS，没有引入参考截图或远程皮肤资源。第三方组件的许可说明见
`THIRD_PARTY_NOTICES.md`；完整包中的 GPL FFmpeg 仍须遵守其分发及对应源码要求。

Electron + Vue 操作台，Python/FastAPI 负责机器人协议、录制证据、树形选择、旁白时间映射和 FFmpeg 导出。当前流程是**选择镜头、完成拍摄、在媒体库保存组合、整篇配音、在工作台预览并导出**。不再自动打分选镜头、随机运镜或凑成 15／30 秒；音乐根据已确认画面的切点自动选取连续片段。

`archive/` 是改版前的完整备份，保持原样。运行、清理和源码交付不应进入该目录。

## 固定镜头怎样拍

在「镜头设置 → 镜头控制」填写矩形范围，选择 4／8 点、速度、基础倍率、缩放倍率和默认镜头，点击「保存固定运镜设置」。原点固定为 `(yaw, pitch) = (0, 0)`；两轴范围都必须跨过零点。协议方向是 **正 yaw 向左、负 yaw 向右；负 pitch 向上、正 pitch 向下**。

| 模式 | 固定顺序 | 片段数 |
| --- | --- | --- |
| 4 点 | 原点倍率往返两段，再原点→左、左→右、右→原点、原点→上、上→下、下→原点 | 8 |
| 8 点 | 上述八段，再加原点→左上→原点、原点→右上→原点、原点→右下→原点、原点→左下→原点 | 12 |

每个点位先在原点拍「基础倍率→缩放倍率」「缩放倍率→基础倍率」两个独立片段，两段始终保留；其余镜头均使用基础倍率。两倍率可在 1～3.5 内分别设置且不能相同，例如 1.2→1.5→1.2。取消所有方向镜头仍保留这两段。变焦需两次新心跳确认实际倍率（容差 0.05 倍）及角度到位；缺失或未到位不会按计时冒充完成。变焦等待上限不少于 15 秒，到位即继续；超时停止后续镜头和导航。

左右边缘分别是 `(yaw_max, 0)`、`(yaw_min, 0)`；上下边缘分别是 `(0, pitch_min)`、`(0, pitch_max)`。四角是这些边界的组合。每个角的去程、回程合为一个镜头。

在「拍摄」巡游清单里启用固定运镜，展开各点的「本点镜头」可覆盖默认选择。镜头始终按表中顺序执行；跳选时先移到镜头起点，这段标为「镜头准备」。选定镜头完成后回原点，再发送下一点导航。底盘行进时不执行镜头序列。没有启用固定运镜的普通录制仍保留原有到点取景窗口。

**到位依据：**每条云台指令发送后，需要两次不同的新心跳；所有目标（原点、边缘、四角）的 yaw、pitch 各允许 ±5°（含边界）。指令仍发送准确目标坐标，原点仍为 `(0, 0)`；镜头准备时已在所需起点容差内则不重复校正。等待预算为较长轴的角度行程／速度 + 8 秒，不把计时结束当作到位。真实硬件的反馈精度和更新频率仍需现场验证。

**异常补发：**固定镜头超时未到位时，最多首次加两次补发，均属于原来的同一个镜头。只有当前连接、当前指令的可信 `ok`，以及该回包之后 3 秒内的新角度和倍率反馈才允许补发；真正写入 WS 前再次检查归属、取消状态和最新起点。busy、拒绝、缺失反馈、断线、其他指令插入、迟到回包归属不明时不补发，停止后续镜头和导航。±5° 内不为了追求零误差反复校正。协议无指令编号，因此曾由心跳或预计时间放行、导致旧 `ok` 无法区分时，本连接内不会再用这种回包批准补发。

**下一条指令的实测起点也包含容差：**yaw 可为 −95°～95°，pitch 可为 −65°～20°；zoom 沿用 0.05 倍容差，可为 0.95～3.55。比如目标 −90°、反馈 −91.2° 时，下一条会保留 −91.2° 作为真实起点，不再因模型校验中断。目标与用户矩形范围仍遵守原限制（yaw −90°～90°、pitch −60°～15°、倍率 1～3.5）；容差外或非有限数值的起点仍拒绝发送。起点校验和到位判定共用 `core/gimbal_limits.py` 的容差。

固定运镜的到位心跳也会解除底层云台指令等待；涉及变焦时还必须有新的倍率反馈，日志记录为 `robot.gimbal.pose_confirmed`。即使无编号的 `ok` 因可能属于旧指令而被忽略，也不会把已确认到位的当前镜头误报为“仍在执行上一条指令”；迟到的 `ok` 仍不能提前放行下一段。仅有角度反馈不能证明变焦完成。

**停止含义：**停止会取消后续任务，并沿用录制停止、下载和恢复逻辑。现有协议没有底盘或云台硬件急停命令；已经发出的运动可能继续完成。停止后不会另发一个用于收尾的云台动作。

## 录像始终保留树结构

```text
一次拍摄（完整原片始终保留）
├─ 完整录制
├─ 起点 → A：行进
├─ A：停留
│  ├─ 原点 → 左        2.5 秒
│  ├─ 左 → 右         4.0 秒
│  └─ 右 → 原点       2.5 秒
└─ A → B：行进
```

- 勾选根节点等于选择完整录制；取消根节点则本次拍摄全部不参与。
- 展开后可选择点位、镜头或行进区间。父节点与后代只算一次；完整录制被选中时只使用原片一次。
- 从全选状态取消一个子镜头，会同时取消「完整录制」的全片选择，保留其余子区间。完整原片文件仍在根节点内，不会隐藏或删除。
- 同一次拍摄选若干镜头，始终作为**一个录制输入**，按原片时间顺序组合。后端直接从原片区间生成组合预览，避免先生成全部子视频再拼接；内部多个裁剪区间不会变成媒体池中的多条录像。时间树和来源区间仍保存。
- 跨拍摄按录制时间排序，拍摄内部始终按树中的先后顺序排列，不受勾选顺序影响。只有媒体库提供树形组合；源视频素材池只接收独立视频。
- 镜头开始、结束来自应用指令与机器人反馈，显示实际记录的区间和时长；中断镜头会标识未完成。相机视频的起始时钟与应用录制时钟仍可能存在偏移，沿用分段校准机制，不宣称帧级硬件同步。

## 具体操作步骤

1. 「镜头设置」保存范围与固定镜头；「拍摄」建立巡游清单，按点选择镜头后开始录制。也可先导入已有录像检查拼接流程。
2. 打开「媒体库 → 选择与组合预览」。自动模式选择录制、组合数量、是否包含点位间移动；手动模式保留原来的点位、镜头、行进区间选择。生成后可逐层预览。
3. 确认本次组合后保存到媒体库。同源组合按原始录制分组，每个组合仍是独立视频，原始录制树保留。可以重复保存不同组合；同一预览重复保存不会生成重复文件。
4. 打开「资产制作 → 按组合画面对齐」，一次选择一个录制下的组合。勾选父级仅全选其组合，切换录制会替换选择。输入文案；「大模型润色」默认关闭，开启后逐条生成对应改写稿，可分别修改。普通导入视频使用「普通旁白」。
5. 点击一次「批量生成旁白」，按队列为每条选中组合各调用一次完整 TTS；默认跳过已有有效旁白。每条实测、调整成功后独立绑定，不需二次确认。右侧展示各组合画面与实际语音时长，失败项单独提示；失败不替换旧绑定。画面预览仍在媒体库。普通旁白及单条调整沿用原有入口。
6. 将组合或其当前绑定旁白「加入媒体池」，或在「剪辑台 → 源视频素材池 → 从媒体库添加」加入。绑定旁白同步入池；勾选或取消组合时旁白同步，操作绑定旁白也会联动对应视频。移出绑定旁白会将对应组合一起移出本次媒体池，不删除文件。
7. 剪辑台保留左侧媒体池、右侧工作台和 2×2 选用汇总。选用音乐、片头／片尾、原声与字幕设置，点击「生成成片预览」。每个输入分别制作一条成片，已保存组合内部不会拆成多个输入。
8. 逐条试听、检查，勾选「已试听并检查，这是本次要导出的成片」，点击「确认导出」。在「渲染队列」查看完成状态；有字幕时仍保留带字幕成片和无字幕母版。

调整选择或设置后必须重新预览。媒体库的“确认”只代表这一次组合符合意图，不限制继续保存其他组合，也不强制把所有点位都选上。

### 自动组合与风格

- 自动组合数量须大于所选录制数量，每次最多 200 条。按录制时间顺序均匀分配；每个点位随机选择一个完整镜头，排除准备和未完成镜头，按原有顺序拼接。自动结果绝不跨录制；手动组合仍可跨录制。
- 可用量是各点位可选镜头数的乘积；同一批次内不重复选择相同镜头组合。容量不足时给出可用量和可行数量，不偷偷把缺额分给其他录制。生成过程串行准备和编码，支持查看进度、取消单项；保存前仍须用户确认。
- 「应用旁白风格」默认关闭，普通和组合旁白共用六种风格：自然讲解（默认）、专业解析、简洁有力、轻松幽默、诗意抒情、文言雅述。开启时仅追加风格上下文，保留自定义系统提示词；关闭后不发送风格字段。
- 组合可选择「自动」，按已选组合的稳定顺序循环分配六种风格。每份改写稿独立保存自己的风格；跳过已有旁白时展示其实际生成风格，而不是当前选择器的值。风格只改变表达，不补造画面事实，不保证某个标点或“留白”会形成特定停顿。

## 准备速度与进度

- 新录制默认只建立时间树与时长，树中子项直接从原片对应区间预览，不自动编码每个节点。点击「重新生成缺失片段」才单独生成子文件；校准只更新区间。已有子文件继续可用，原片离线时仍可选已有子文件组合。
- 保存组合前的预览直接裁剪所选原片区间，保持原有树顺序、音画区间与旁白绑定。此阶段在「媒体库 → 组合与预览」或「剪辑台」显示准备、等待资源、生成、校验及已用时间；可点击「取消生成」。确认导出后才出现在「渲染队列」，这两种进度互不混用。
- Windows／Linux 先用实际短视频测试 NVIDIA `h264_nvenc`，本进程按 FFmpeg 文件缓存结果；可用时采用硬件编码。不可用或明确的硬件初始化错误会退回 `libx264`，保留原 CPU 参数；普通素材错误不会反复换编码器重试。Mac 继续使用现有 CPU 路径。界面和后台日志记录所用编码器与回退原因。
- 编码进程共用并发上限，等待时可取消；编码连续 120 秒没有时间进展会停止并报错，清除未完成文件。已完成片段、原片、组合和原有旁白不会因此被覆盖。GPU 实测速度仍需在客户 Windows 上用同一素材复测，不能用 Mac 模拟测试代替。

## 旁白、备注与时长：Q&A

**拍摄备注还在使用吗？** 仅当组合来自同一条原始录制时，备注作为大模型理解画面与点位的上下文。口播事实以用户输入文案为准，拍摄指令不会自动变成台词。跨录制组合保留来源记录，但不把备注、点位资料传给大模型，也不执行 BAAI 匹配。

**跨录制怎样制作旁白？** 后端使用简单提示词，只包装本次文案、补充要求和 X＝实际组合总时长。整篇润色、用户审阅、一次 TTS、实测时长、0.9～1.1 倍微调、成功后自动绑定照常保留。两条录制先存成一个组合再参与拼接，仍按原始来源识别为跨录制；来源不完整时也采用简单模式。

**能查看或修改后台提示词吗？** 「展开提示词」显示系统规则和实际输入，二者与下一次润色共用同一个后端构造函数；查看不会调用大模型。可以单独填写「本次补充要求」，或启用「自定义系统提示词」编辑全部系统规则，随时「恢复默认」。切换组合恢复默认；自定义规则不能改变后端的来源分流。单录制默认先将用户原文事实对应到点位，再一次性润色整篇；完整拍摄备注只交给事实对应阶段，不按逗号拆成备注。展开面板可查看两步规则，生成后可查看每步实际输入和缓存复用情况。自定义系统提示词保留原来的整篇单次调用，仍要求有效画面 ID 的 sections JSON；跨录制返回整篇正文。无备注的单录制组合必须填写「本次补充要求」才能润色；关闭润色可直接 TTS。

**为什么不让小模型一次包办全部工作？** 默认流程由 `services/grounded_narration.py` 实现：原文分成带稳定编号的事实单元（条件句保持完整），LLM 为每条事实选择唯一点位，避免在总览和专门点位重复讲解；未知对应返回空值。程序按点位时长计算保守写稿预算，只选完整事实，再用一次请求润色所有点位的整篇旁白。首次每条组合最多两次 LLM 调用，1、3、5、12 个点位均相同；点位增加仍会增加请求内容与生成时间。这是每条组合的上限，不是整个批次只调用两次。超出预算、丢失数字或关键限定词、漏掉段落时，仅对应段落回退到选中的原文事实；返回格式无效时全部使用已选事实，不自动付费重试。网络与服务商错误照常报错，不伪装成生成成功。没有对应依据或完全放不下时不猜；部分点位留白，全部不可用则返回明确提示。移动段默认留白，但用户明确说明要讲解时仍支持。已有真实 TTS 超时反馈可进一步收紧对应点位预算。

同一服务进程最多缓存 128 个已完成的精确输入结果；事实对应缓存不依赖风格或时长，整篇改写按所选事实、点位预算、要求和风格复用，模型或密钥改变也会失效。错误格式的事实对应或整篇稿件不缓存。风格变化可复用事实对应，但整篇润色需要一次新调用；完全相同输入可全部命中缓存。缓存只减少 LLM 调用，不合并组合、不复用不同组合的音频绑定。机械检查不能证明任意语义完全正确，实际时长仍以 TTS 检查为准。

两次调用的真实 API 实验与限制见 `output/two-call-narration-20260921/report.md`；本地 BAAI 的匹配实测见 `output/baai-routing-20260921/report.md`。 后续风格示例、条件同义、数字单位与跨点照搬检查的实测见 `output/narration-refinement-20260921/report.md`。组合默认润色采用具体句式示例，关闭风格即移除此层；普通／跨录制／自定义提示词保持原包装。只对少量明确条件表达作规范化，新增否定、常见数值单位改变、明显照搬其他点位原文会触发本地回退；这些检查不是完整语义证明。

**是一条旁白，还是许多小旁白拼起来？** 一份审阅后的完整文案，一次完整 TTS 请求，一条原始音频。点位与行进区间只是文案和实测检查的时间参考，不各自合成录音。

**怎样对齐组合？** 同一原始录制内，大模型根据画面顺序、实际区间、拍摄备注和原文安排整篇文案。合成后使用真实音频时长与可靠的逐词时间；已有段落绑定优先，BAAI 辅助检查和找回修改后的对应关系。相似度门槛和领先第二候选的差值共同限制自动匹配；不确定、过渡或逆序内容保留为待核对，不调换画面顺序。跨录制仅做整篇时长适配，不承诺逐点对齐。

**LLM 返回的稿件还可以改吗？** 可以直接在「审阅改写稿」中修改，再选「采用改写稿」。手动修改不会清空原来的段落参考；未改部分沿用参考，改动部分重新匹配。若要重新润色，可重新开启润色开关；超时时可点「按实测时长精简文案」。合成后修改文字需要重新合成语音。

**怎样控制播放速度？** 基础速度可选 0.9、1.0、1.1 倍；默认原速，可允许自动在 0.9～1.1 倍内微调。可靠时间与完整对应关系都具备时，在真实词间空隙处分段处理同一音轨，按需等待下一画面；所有词和字幕使用相同时间变换。缺少可靠对应时只调整整条速度。不是分段调用 TTS；最终仍是一条完整旁白。播放速度调整复用内部原音频缓存，不消耗新一次 TTS。实际音频放不下时提示精简，不截断语句、不拉长画面、不自动付费重试。

**没有可靠逐词时间怎么办？** 可以同步试听，并明确提示无法精确检查或调整局部对应。BAAI 只判断语义，不能生成音频时间戳。此时按实际整条语音区间显示整句，不把字数估算当成真实词级时间。

**旁白何时跟视频绑定？** 点击「生成旁白」后，完整音频、调整后的字幕时间都保存成功，才更新视频旁 `.composition.json` 中唯一的有效绑定。失败或超时均保留原绑定；重调速度写入新文件，不覆盖正在使用的旧音频。绑定通过持久 UUID 关联，入池、选用、取消、重启、改名和导出继续一对一联动。历史旁白不能代替当前绑定；入池不自动勾选剪辑，勾选任意一方才同步选用另一方。

**字体和已有旁白怎么查看？** 字体菜单用各字体自己的字形显示名称和固定字幕样例。「已有旁白」展开后在固定高度内滚动，可按名称搜索、筛选当前组合；点选一条使用共享播放器试听，列表不会堆出大量播放器。

**最终长度由谁决定？** 由已确认的画面长度决定，片头、片尾另计；编码按 30 fps 的帧粒度校验。音乐从整首中自动选择与所需时长、画面切点和首尾衔接更合适的连续片段；音乐较短时循环补足，不改变视频长度。默认音乐从片头结束后开始，开启「音乐覆盖片头、片尾」后覆盖整个成片。组合旁白始终从主体开始，字幕与它一起偏移。

**源文件能否清理？** 尚未保存的组合预览会保护其依赖素材，可通过「移除预览」释放。已保存组合是独立文件，保留层级来源记录，不再依赖原片才能播放。正在制作或导出的素材仍受占用保护。

## 协议与诊断要点

- 机器人地址只来自「设置 → 机器人硬件 → WebSocket 地址」中保存的配置。空地址不会自动猜测连接。Ping 只检查连接，不启动拍摄。
- 到点依据属于当前导航指令的 `goal_status`，不等待 `object_status`、不要求识别或对齐目标物。导航归属、新旧连接隔离、录制会话恢复继续由原协议层处理。
- 心跳中的 `system`、`map`、`navigation`、`task`、`gimbal` 各有职责；`ready` 或 `goal_status=done` 不能证明相机录制成功。相机 ACK、录制状态、停止结果及媒体下载校验分别检查。
- `fail` 是机器人对相应请求的失败回复；仅凭这个词不能断定是命令时序、相机状态还是设备内部问题。结合 `logs/diagnostics.log` 同一连接、请求和录制会话的前后记录检查。
- 实际 yaw/pitch 使用心跳，固定 zoom 是应用下发值；不能把下发成功当作硬件已到位。
- `tools/robot-control-console.html` 是独立直连调试页：手动角度控制和固定 4／8 点停稳测试，固定 mode=1、zoom=1。它不控制底盘、不录制、不复用正式应用设置。不要与正式应用同时连接同一设备。已移除旧随机四区域与比例循环。

更完整的原协议约束见 [机器人适配器约定](docs/robot_adapter_contract.md) 和 [现场协议资料](docs/live_robot_api_requirements.md)。

真实 LLM 提示词评估使用 `scripts/evaluate_narration_prompts.py`，需显式运行并使用本机已启用的大模型配置；会产生实际 API 用量，不调用 TTS。输入为场景 JSON，输出保存实际提示词、模型返回与解析结果，不保存密钥。使用 `--prompt-overrides` 可先验证候选规则，改规则后使用新输出目录，避免与旧结果混淆。2026-09-20 的汽车、酒店、咖啡机、工业泵与保温杯实测见 `output/prompt-evaluation-20260920/report.md`；后续小模型任务拆分、真实失败候选及当前实现验证见 `output/prompt-practical-20260920/report.md`。默认规则收紧事实与篇幅边界；LLM 返回合法节点上的空备注可省略，未知节点、重复节点及手动提交的空绑定仍拒绝。字数筛查不代表 TTS 实测时长，风格与点位语义对应仍有模型误差。

当前保留 NumPy、ONNX Runtime、tokenizers 和轻量 BAAI 模型用于本地文本对应，按需加载、限制推理线程与缓存。librosa 0.11 已恢复，用于音乐重音与能量特征分析；PySceneDetect、OpenCV、PyAV 仍未恢复。FFmpeg／ffprobe 负责媒体探测、拼接、旁白微调、混音、字幕和编码。开发环境模型准备：`python scripts/prepare_assets.py --semantic-only`；发布流程自动校验并打包。

旁白单次输出预算按内容规模分配，普通旁白与组合整篇润色为 2,048–8,192 token；这不改变视频时长或文案字数目标，也不代表启用额外推理。单录制默认组合仍最多两次 LLM 请求。已实测的 `doubao-1-5-lite-32k-250115` 在事实分配和整篇结构化润色时使用 JSON 模式，其他模型不自动套用；普通旁白保持纯正文。后端 `llm.response.received` 日志记录结束原因、用量、耗时和响应 id，不记录密钥或文案。截断及非正常结束不会当作完成稿，也不会自动重试。31 次真实响应与预算对比见 [单次预算实测](output/doubao-budget-20260921/report.md)。


### 音乐标签与自动选段（2026-09-21）

- 「媒体库 → 导入本地媒体」选中音乐后，选择已有标签或新建标签。默认只有「轻快、舒缓」；未选标签归入「未分类」。音频链接导入在下载并识别类型后选择标签。已有音乐可通过「标签」按钮修改。
- 剪辑台的音乐池及「从媒体库添加 → 音乐」按标签分组。多标签音乐可出现在多个组，但始终是同一个素材 ID，不会重复入池或重复混音。标签跟随复制/引用导入、扫描、重启和应用内重命名保留。
- 标签词表与文件对应保存在 `data/media-library-music-labels.json`。`GET/POST /api/music/labels` 读取/新建标签，`PUT /api/media/{media_id}/music-labels` 更新音乐标签。只有音乐可以分类，旁白与视频不参与。
- 实际渲染前，`services/music_selection.py` 用 FFmpeg 解码为低采样率单声道，librosa 提取重音强度和能量，再根据固定切点、有效声音覆盖和首尾衔接评分，选择一个连续片段。保存组合内部的镜头边界也参与匹配。它是声学评分，不是理解音乐情绪的模型，也不保证每个切点都恰好落拍。
- 配乐调整不移动画面、TTS 或字幕。已有片头/片尾覆盖规则保留；正常界面不展示选段起止、不增加「换一段」。成片与无字幕母版使用同一段配乐。
- 特征缓存位于 `.cache/music-analysis`，按文件路径、大小、修改时间和算法版本失效。解码限时 40 秒，分析独立进程限时 60 秒；取消时终止进程。超过一小时的音乐或分析失败会记录原因、提示并回退从头播放。首次底层编译较慢，此后缓存复用。
