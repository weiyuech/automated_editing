# 可控拍摄与精确拼接

`archive/` 是 2026-09-18 的完整基线备份，禁止修改、清理或打包该目录。

## 产品约束

- 底盘仍按已有协议逐点导航，不猜造速度或运动时长字段，也不恢复目标物对齐。
- 到点后完成该点选定的确定性镜头序列，才允许发送下一点。原点固定为 yaw=0、pitch=0；用户范围定义矩形，范围必须包含原点。
- 四个边缘点为 (yaw_max,0)、(yaw_min,0)、(0,pitch_min)、(0,pitch_max)，四个角为矩形四角。实际左右沿用机器人协议的正 yaw 向左约定。
- 拍摄证据保持树结构：一次拍摄 → 点位/行进 → 镜头片段。每个节点显示实际起止和时长；完整原片始终保留。
- 用户可跨拍摄、跨树层级选择，父节点和其后代不重复拼接。输出严格遵从树中的先后顺序和时间区间，不随机挑选，不补足到 15/30 秒。
- 先预览拼接，再明确确认最终组合。确认绑定素材与区间；修改选择后必须重新确认。完整视频被选用时优先使用一次。
- 音乐从头使用，长于成片时裁至成片结尾。片头/片尾与旁白均须在预览和最终时长中清楚体现。
- 一条完整旁白绑定一份已保存组合，以点位和行进区间提供段落参考；已有拍摄备注提供映射上下文，不自动变成口播事实。LLM 整理用户文案，TTS 合成后以音频实际时长和供应商时间戳校验，禁止把字数估计冒充真实时长。
- 整条旁白超时不绑定、不截断语句、不延长视频，显示实际差额并由用户审阅后重新合成；每次点击只进行一次完整 TTS。局部错位提供提示，由用户试听微调。
- 删除自动场景检测、画面打分、节拍检测和本地语义模型的运行依赖及打包逻辑。FFmpeg/ffprobe、现有录制恢复与媒体安全保护继续承担对应职责。

## 实施顺序

1. 梳理并替换随机运镜为有限、可选择的镜头序列；记录真实片段边界。
2. 扩展树形分段与组合选择，建立有进度的预览、确认、精确拼接入口。
3. 用对齐开关统一旁白制作界面；整篇润色、人工审阅、一次完整合成和实测校验。
4. 简化剪辑界面与最终渲染，删除退役依赖、旧分析与自动规划入口。
5. 以模拟机器人、合成视频/音频及真实 FFmpeg 检查导航顺序、树选择去重、拼接时长和旁白边界；更新使用说明。

## 已确认的规则

- 4 点模式为上下左右六段；8 点模式再追加四个角往返片段。
- 短画面放不下旁白时，先精简文案，再合成并校验实际语音时长；仍不合适时明确提示。
