# 巡游完整录像与分段录像

本说明对应 0.1.7 源码中的实际行为。一次巡游仍只向机器人发送一次开始录制和一次停止录制；应用拿到完整录像后，才在电脑上按导航事件生成分段录像。分段功能不要求机器人同时录制多个文件，也不改变字幕、旁白或成片分组。

## 用户看到什么

媒体库以“一次拍摄”为一条主记录，展开后按顺序显示：

```text
展厅巡游 · 2026-09-17 09:30
  完整录制
  开始准备
  起点 → 展厅#1 · 行进
  展厅#1 · 停留
  展厅#1 → 展厅#2 · 行进
  展厅#2 · 停留
```

每个分段显示原片区间、生成状态和实际占用空间。`等待生成`、`生成中`、`生成失败`、`文件已移走`都是真实状态，不会把临时文件当作成功素材。

媒体库中的“边界偏移”用于现场发现机器人事件与相机文件存在固定时差时整体校准。新结果写入新的版本目录；正在剪辑的旧文件不会被覆盖。替代版本成功且没有任务继续读取旧文件后，旧版本才会清理。

## 怎样选用

### 自动剪辑

- 一次拍摄始终占一个源视频名额，不会因为有十个分段就冒充十次独立拍摄。
- 选择“完整录制”时，剪辑直接使用原片。
- 选择若干分段时，后端按原始时间顺序合成为一个临时剪辑输入，再交给现有分析和剪辑流程。
- 选择了全部分段且原片仍在时，直接复用原片；不会无意义地重新编码。
- 原片已移走时，界面只允许选择仍存在的分段。一个分段可直接使用；多个分段会按时间顺序组合。缺失的内容不会被伪装成完整录像。

### 手动微调

素材选择器以拍摄分组展示“完整录制”和每个可用分段。分段在界面中有独立选择身份，但提交时仍携带拍摄主记录 ID 和真实子文件路径。后端会用拍摄清单核验这对 ID/路径；任意外部路径或伪造路径不能借此进入渲染。

## 边界依据

分段时间轴使用半开区间 `[start, end)`，连续覆盖完整视频，不重叠也不静默丢掉流程间隙。

- `goal_going` 优先作为行进开始证据。
- 没有 `going`、但目标指令确实写入时，使用写入时刻并标记为估计边界。
- 只有属于当前目标的 `goal_done` 才开始点位停留。
- 指令被拒绝且没有导航证据时，不生成虚假的成功行进或停留。
- 状态不明确的画面保留为“状态未确认”。
- `object_status` 不参与到点判定；目标物未对准不能阻止拍摄。

机器人协议没有提供相机文件的逐帧时钟，因此应用保存录制指令写入、机器人反馈和应用单调时钟，并明确把文件边界称为估计值。校准只能修正稳定的整体偏移，不能把延迟不稳定的心跳变成物理帧级真值。

## 文件、声音和恢复规则

- 完整录像保留在 `data/downloads/`；分段保存在 `data/capture_segments/<拍摄哈希>/<时间轴版本>/`。
- 裁切会解码并重新编码，不使用关键帧不精确的任意位置流复制。
- 音轨明确存在时保留声音，明确不存在时生成无声分段；探测结果不确定时本次生成失败，不会误发一个永久无声的视频。
- 视频先写临时文件，时长校验通过后才原子发布；云台轨迹先写，拍摄来源说明最后写，避免后台提前登记半成品。
- 拍摄分组清单持久化在应用数据目录。重启后，`生成中`恢复为待处理，只补未完成项目。
- 旧版本没有 `recording_events` 的历史旁录不会在升级时突然批量转码。
- 分组清单是可重建的派生信息。它损坏时会停用分组功能并记录错误，但完整原片仍正常出现在媒体库中。

## 删除与空间

- 删除单个分段只移走该分段和它的拍摄/云台说明；普通扫描不会偷偷重新生成，用户明确点“重新生成缺失片段”后才会补做。
- 删除完整原片不会连带删除已经生成的分段；这些分段仍可预览和剪辑。
- 删除全部可见成员后，应用会在没有任务占用时清理该拍摄的临时组合输入和派生清单。
- “一键清理缓存/预览”也会清理不再使用的分段组合输入，但不会删除正式分段。排队或运行中的剪辑所使用的文件会跳过。
